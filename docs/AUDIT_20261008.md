## Measured results and their limits

The neighbours baseline scores 0.0969 on the frozen outer split, versus degree 0.0733. Controls narrow that result: on new links, neighbours is not shown to beat degree under both required exclusions (`findings/CONTROLS.md`). Do not describe the entire baseline gain as new biological prediction.

Model tuning uses a different, inner split. LightGCN's validation 0.0743 versus neighbours 0.0712 gives +0.0031, interval -0.0058 to +0.0120. This does not establish improvement, and setting selection used those same validation links. The amended graph-model grid has 44 settings; old 24-setting choices do not settle the expanded grid. Shard logs show partial progress, not current process liveness.

CTD withholds 46.5% of searchable one-source pairs, above the prospectively stated sample interval of 26.4–44.7%. Monarch also misses its stated deployment interval. The later comparison using all sampled pairs is exploratory; it does not erase that failed check. CTD accounts for 82.5% of withheld pairs and lies only 3.5 percentage points below the permitted cost. Its planted recall estimate rests on 100 pairs. Preserve the cut and test a new, larger sample before making a robust pruning claim. A low publication lift is weak support, not proof that an association is false.

## Two model preflight issues found in code

`src/pharos_gap_kg/model.py:graph_for` returns counts for the joined context graph. `setting_file` and `reuse_committed` use these counts in cache identity. Two graphs with changed edges but equal counts can share an identity. Include canonical edge content, node ordering, source/configuration and implementation identity; dry-run existing cache migration before reuse. This is a code risk, not evidence that stored results are already wrong.

`final()` checks the chosen record's `complete` flag but does not verify its grid against the current protocol or establish that the file is committed. An old record marked complete can survive a later grid amendment. Add explicit settings/configuration provenance checks and a reproducible freeze manifest before the one-time outer test. A remote checkout without `.git` needs the verified manifest rather than an impossible Git check.

Do not patch running shards in place or delete their cache. Finish/stop them under their owners, establish exact input identities, then migrate verified results or rerun only records whose provenance cannot be established.
