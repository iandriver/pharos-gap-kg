## Summary

`pharos-gap-kg` builds a knowledge graph from the public Pharos 3.19 database and serves it through
eight typed questions that a person or a language model can ask. Every edge resolves to the source
row, the published file and that file's digest. Every edge the pipeline removes stays
in the graph as a typed gap, which names the rule that removed it and the evidence that would restore
it. Every prediction is scored on links reported after the data it was made from.

Where it stands on each criterion and on the challenge's key question:

- **Usability.** Using the typed questions, three small hosted models each got 34 or 35 of 35
  code-graded tasks right, on three separate frozen task sets. No person has tested it yet.
- **Pruning.** Rules are scored on planted false pairs against a bar stated in advance. A cut on PubMed
  co-mention clears the bar on five of Pharos's eleven disease sources and is applied: 7,248 of 324,882
  rows are withheld as typed gaps. A model that reads the abstracts does worse than that cut.
- **Explainability.** `why` returns the studies, papers and years behind an edge, down to the digest of
  the file they were read from. Where there is no edge it says what evidence exists nearby.
- **Standards.** The graphs are KGX files with BioLink categories and predicates, and all three pass
  the `kgx-gaps` conformance suite.
- **The key question.** On links reported later, no graph model has beaten a parameter-free neighbour
  score computed from Pharos links alone, and Pharos's other content has not added to that score. One
  small fitted score that adds gene position does beat it, on links first reported from 2023. The
  graph models that take the enriched graph as input are not fitted yet.

## What is built

| step | what exists | not done |
|---|---|---|
| Ingest | A registry of public files with pinned digests, a resumable fetcher, and a reader that turns the published MySQL dump into typed tables with no database server. From Pharos 3.19: GWAS links, interactions, pathways, GO terms, compounds and eleven disease sources. From outside it: the EFO ontology, Ensembl gene coordinates, Pharos 4.0.0 development levels and the GWAS Catalog release of 5 Oct 2026. | An agent that proposes the mapping for a table it has not seen. |
| Filter | A client model turns a question in plain language into one of the eight typed questions. A name is resolved against the graph or refused, and every answer is as of a year. | Returning the subgraph behind an answer as KGX. |
| Clean | Declared pruning rules, each scored on planted false pairs. A withheld row stays as a typed gap. | Three disease sources that no rule reaches. |
| Limit | The questions read a 12 MB bundle of tables. | Nothing further; the graph is small. |
| Maintain | Every input and derived file carries a digest. The fetcher refuses a published file that changed, and the question layer refuses a bundle that does not match its manifest. | Re-deriving only what a changed input affects. |

The graph of dated links holds 295,327 GWAS links between 18,005 of Pharos's 20,412 protein targets
and 2,247 traits, from 12,335 studies in 3,141 papers. The graph of disease sources holds 317,634
edges and 7,248 gaps. A third graph holds 23,236 target-level gaps.

Coding agents wrote the pipeline (Claude Code, with Codex as a second reviewer) and I directed them.
Each measurement was defined in `docs/PROTOCOL.md` and committed before it was computed, and every
change made after seeing data is a dated amendment there. The built pipeline is deterministic code.
At question time a model only chooses which question to ask and words the answer.

## Status by judging criterion

### Usability (40%)

Eight questions run from the command line or from any Model Context Protocol (MCP) client: `find`,
`known`, `why`, `connect`, `predict`, `whats_new`, `gaps` and `status`. A name that matches nothing
returns "not in the graph". An absent link is never reported as a negative. `connect` answers across
two hops, for example the 45 targets that Parkinson disease and Crohn's disease share. A prediction
carries the parts of its score and how often candidates at its rank were later reported.

Each test put 35 code-graded tasks to three small hosted models (mercury-2.5, deepseek-v4-flash,
glm-5.3-flash, in that order below) under three conditions. Tasks and expected answers were frozen
before any model saw them.

| tasks on | typed questions | SQL over the same tables | no tool |
|---|---|---|---|
| the first seven questions | 35, 35, 35 | 31, 33, 35 | 1, 4, 1 |
| target-level gaps | 34, 35, 35 | 33, 33, 34 | 3, 11, 9 |
| rankings and their rates | 35, 35, 34 | 32, 34, 35 | 0, 0, 0 |

No model answered about an invented gene as if it were known. On the share of tasks done correctly,
the typed questions beat SQL on the first set (+0.057 [+0.010, +0.105]) and are not shown to on the
other two (+0.038 [+0.000, +0.086] and +0.029 [-0.019, +0.086]). Each set followed a development
round, and the faults that round found, in the test or in the tools, were fixed before the fresh set
was written. All rounds are in `findings/USABILITY.md`.

Not done: no person has used it, and I wrote the tasks.

### Accuracy and pruning (30%)

A pruning rule is scored by planting false pairs in a source and counting how many it withholds, and
how many real pairs it withholds with them. The bar, stated before any rule ran: at least 80% of
planted pairs withheld, at most 50% of real pairs that only one source asserts.

| rule | sources that pass, of 11 |
|---|---|
| in-graph corroboration: another source, a related disease or an interaction partner has the pair | 1 |
| no PubMed abstract mentions the gene with the disease | 2 |
| a cut on PubMed lift: co-mention against chance, cut set on half the sample and scored on the other | 5 |
| a model reads the abstracts and must quote the passage it relies on | 3 |

The in-graph rule withheld 38.9% of 16,250 planted pairs. Its failing criterion is "an interaction
partner has the same disease", which holds for most random pairs. At the same cost in real pairs the
model reader withholds 81.1% of planted pairs and the lift cut 87.8% (-0.067 [-0.103, -0.037]), so
the rule that needs no model is the one applied. No source's own confidence field orders its pairs
the way the literature does.

The cut is applied to the five sources it passes on. Of the 7,248 rows withheld, 5,982 are CTD's.
Each is a gap record carrying the papers counted, the lift and the cut.

Limits: the lift cut was added after the first counts were seen, and the record marks it so. CTD's
cost over all its one-source pairs is 46.5% against the bar of 50%, and its pass rests on 100 planted
pairs. Expression Atlas, DrugCentral Indication and AmyCo are out of reach of every rule tried. A
full-text check on the last two is in progress.

Link prediction is under "The key question" below.

### Explainability (20%)

An edge id is a digest of what the edge claims. `why APOE "Alzheimer disease" --as-of 2010` returns
the four GWAS studies behind that edge with their PubMed ids and years, the first in 2007, and says
25 more came later. `graph lineage` follows the same edge to the SHA-256 of the Pharos file it was
read from.

Where there is no edge, `why` says that no study in this source had reported one by that year, that
this is not evidence of no association, and what exists nearby: links to related traits, links at
neighbouring genes, and the target's rank among the trait's candidates.

A candidate comes with a rate measured on later links. Of the ten highest candidates for a trait,
8.9% were reported in 2023 to 2026, against 0.49% of all candidates. Where no earlier link at the
locus or under a related trait explains the candidate, the rate is 4.0%.

### Standards (10%)

Nodes and edges are KGX. The dated graph uses five BioLink categories (`biolink:Protein`,
`biolink:DiseaseOrPhenotypicFeature`, `biolink:Disease`, `biolink:PhenotypicFeature`,
`biolink:BiologicalProcess`) and one predicate, `biolink:genetically_associated_with`. The graph of
disease sources uses three more predicates (`biolink:gene_associated_with_condition`,
`biolink:correlated_with`, `biolink:target_for`). Each edge names its primary knowledge source, its
aggregator, its knowledge level and its agent type. All three graphs pass 10 of 10 checks of the
`kgx-gaps` conformance suite. One predicate is outside BioLink, `pharosgapkg:evidence_missing_for`
on target-level gaps, with a registered rationale.

Of the 1,404 traits with a link by 2018, 505 carry an ontology id that has since been retired and
replaced. Lineage is computed on the live terms and the graph carries the ids as published.

Not done: a review by someone who works with BioLink of whether each predicate is the most specific
that fits.

## The key question: does the built graph predict held-out links better

Links are dated by the first GWAS study behind them, since no other Pharos link carries a date. There
are two tests. The first trains on the 99,435 links reported by 2018 and scores 130,369 later links
over 540 traits. The second trains on all of Pharos 3.19 and scores 194,017 links first reported from
2023 in the GWAS Catalog, over 1,110 traits. The measure is mean average precision over traits, with
95% bootstrap intervals over traits. Each fitted model was tuned on earlier years, frozen, and scored
on its test links once.

Three terms recur below. The neighbour score ranks a target for a trait by how similar that trait is
to the traits the target is already linked to; it has no fitted parameter. Lineage is a trait's
ancestors and descendants in the EFO ontology. Position is a gene within 500,000 bases of a gene that
already has the link.

| test | scorer | score | against neighbours |
|---|---|---|---|
| links after 2018 | chance | 0.0178 | |
| | target degree | 0.0733 | |
| | neighbours: parameter-free, Pharos links only | 0.0969 | |
| | neighbours blended with Pharos context, best of five kinds | 0.0886 | -0.0083 [-0.0146, -0.0031] |
| | matrix factorisation | 0.0906 | -0.0063 [-0.0155, +0.0025] |
| | LightGCN | 0.0825 | -0.0144 [-0.0232, -0.0064] |
| | LightGCN with lineage and position edges | 0.0962 | -0.0008 [-0.0108, +0.0092] |
| | neighbours, degree and gene position, six fitted weights | 0.1037 | +0.0067 [-0.0009, +0.0151] |
| links from 2023 | neighbours | 0.0947 | |
| | LightGCN with lineage and position edges, retuned | 0.0913 | -0.0033 [-0.0092, +0.0024] |
| | neighbours, degree and gene position, two fitted weights | 0.1012 | +0.0066 [+0.0031, +0.0102] |

No graph model beats the neighbour score on either test. Each kind of Pharos context (interactions,
pathways, GO terms, shared compounds, disease sources) scores 0.019 to 0.032 alone and lowers the
neighbour score when blended with it.

The one gain comes from gene position. The scorer that wins the second test was the only one of
eight candidates, tried in 28 variants, to beat neighbours when the whole procedure was rehearsed
inside the training years (+0.0038 [+0.0008, +0.0077]). It was named for the second test before any
scorer read those links. Its
gain is at loci the training data already holds. 35.5% of the 194,017 test links follow from an
earlier link at the same locus or under a related trait, and on the rest the scorer is not ahead of
neighbours. The question layer ranks by it and says so.

Still open: the two graph models that take the disease sources as edges, one with the withheld rows
and one without. They are declared in the protocol and not fitted, and they need a GPU. They are the
direct test of the key question and of whether pruning helps prediction.

## Gaps, carried over from the application

The application proposed a gap atlas for three neurodegenerative diseases. The brief asks for a
graph built from Pharos, so the entry was built on Pharos. What carried over is the typed gap.

Besides the withheld rows, the graph holds what each target lacks for the next Pharos development
level. For 5,499 Tdark targets, Pharos's least-studied level, the gap names the nearest criterion and
a distance to it. Tested against Pharos 4.0.0, that distance ranks the 788 of 5,314 targets that were
promoted with a ROC area of 0.859 [0.845, 0.872], which is +0.066 [+0.055, +0.077] over the PubMed
score alone. Of targets one criterion short and nearest to it, 53.6% were promoted.

## Findings about the data that other teams may need

- The April 2023 (3.16) and April 2024 (3.19) Pharos databases hold identical link tables. 70 of the
  89 tables they share are identical, among them GWAS, disease, interaction, pathway and ligand
  activity. A split by release date has no later links to score.
- One source in the Pharos `disease` table, "JensenLab Experiment TIGA", is the GWAS data under
  another name. Used as context for held-out GWAS links it scores 0.60 where the neighbour score
  reaches 0.10, by reading the answers. A test on GWAS links has to leave it out of the context.
- A fifth of the later GWAS links (26,346 of 130,369) follow from an earlier link at the same locus
  or under a related trait, and the 130,369 links are 31,885 loci. Counted once per locus, target
  degree falls from four times chance to twice.

## Run it

`README.md` lists every command in order. `make check` runs every self-test. The questions:

```bash
python -m pharos_gap_kg.ask why APOE "Alzheimer disease" --as-of 2010
python -m pharos_gap_kg.ask predict "type 2 diabetes mellitus" --unexplained-only
python -m pharos_gap_kg.ask gaps --family Kinase
python -m pharos_gap_kg.server        # the same questions over MCP
```

The record of what was measured, negative results included, is in `findings/`.
