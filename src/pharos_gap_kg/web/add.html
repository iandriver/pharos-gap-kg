Adding a table from a paper

A scientist brings a table from a paper the graph does not hold, and a few lines saying what the paper is. No code is written for that table. A model proposes how to read it, code checks each proposal and says why it refuses one, and the person reads the accepted mapping and decides whether it joins. Below is every run of the entry, step by step, as the records hold it.

The sheetThe model sees the first rows of every sheet in the file and names the sheet to read and the row that holds its column names. Code checks that the sheet can be read.
The mappingThe model proposes how each row becomes an edge of the graph, in the Biolink model. Code runs nine checks against Biolink and the data, and sends a refused proposal back once with its reasons. If both are refused, a second model starts over.
The personThe accepted mapping is shown field by field, with how many links it would make and the rows that gave no gene. The table joins only when the person says so. No model joins anything.

Try it with your own table

On your own machine, with the server installed for Claude Desktop (python -m pharos_gap_kg.desktop install, see the repository's docs/ASK.md), give Claude the path of your file (CSV, TSV, XLSX or ODS) and the paper: its citation, journal, date, DOI, licence, the disease in words and what to add. Claude's model reads the cards (add_card), checks its proposals (add_check) and joins (add_join) only when you say so. No key is needed. This hosted server is read-only and adds no table.

What the checks do not say

An accepted mapping has the right form and fits the data: the sheet reads, the Biolink classes and predicates exist and fit each other, and enough rows give a gene and a trait of the graph. It is not shown to be the reading the authors meant. That is why the person reads it before it joins, and why each run below states a check against an outside record, fixed before the run.
